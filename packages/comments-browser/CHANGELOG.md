# Changelog

## Unreleased

## 4.0.0 - 2026-11-25

### Added
- Add `@verbb/comments-browser`, the renderer that draws every Comments thread in the browser, built on `lit-html` and `@verbb/comments-core`. It's released alongside the Comments plugin at the same version.
- Add `startComments()`, which starts every thread on the page, threads added later and Turbo Drive's page swaps, hands over to a copy already running, and leaves threads marked `data-comments-auto-mount="false"` for `Comments.mount()`. Importing the package starts nothing.
- Add `Comments.configure()`, `mountThread()` and `Comments.setTheme()`, and a controller for each thread with `load()`, `refresh()`, `openEditor()`, `closeEditor()`, `showFormErrors()`, `clearFormErrors()`, `setTheme()` and `destroy()`.
- Add the three load modes: `visible`, which loads a thread just before it scrolls into view, `button`, which waits for **Show comments**, and `eager`. A link to a comment loads its thread straight away in any mode.
- Add the comment editor: a member's new comment collapsed to one line, Post waiting for some text and saying why when pressed, ⌘↵ or Ctrl+Enter to post, a character ring near the limit, a draft kept in the browser, and Editor swapped in for rich authoring when someone starts writing, with what they typed.
- Add an author's own pending comment, with a note that it's waiting for approval, and a visible "Write something first." when Post is pressed on an empty comment.
- Add `themeConfig` for ten controls (`primaryButton`, `secondaryButton`, `quietButton`, `input`, `textarea`, `select`, `checkbox`, `radio`, `link` and `avatar`), with classes and attributes added to every element of a control and `resetClass` to drop Comments' own styling classes while keeping the identifying ones and every `data-comments-*` attribute.
- Add part overrides, as functions or registered custom elements, for the header, the empty state, Show comments, the loading line, notices, each comment and its avatar, author's name (`authorName`), badges, meta line, content, field values, actions, review strip and placeholder, the sign-in card, "Posting as" and the custom fields (`formFields`).
- Add the light, dark, auto and None themes, `darkSelector` for a site's own dark-mode toggle, and the `css/comments.css`, `css/comments-base.css` and `css/comments-theme.css` stylesheets, with the tokens in `@layer comments-tokens`.
- Add the `--comments-gif-max-size` token, the square a comment's GIF fits inside, with `comments__gif--portrait` on GIFs taller than they're wide.
- Add `markup/classes.json`, the class names the renderer draws, each marked stable or internal.
- Add Comments 3's event names, such as `comments:submit` and `comments:upvote`, dispatched on `document` beside today's events for a thread Craft renders with the plugin's `compatibilityMode` on, which marks the mount point `data-comments-compatibility`.
- Add the `verbb-comments` Trusted Types policy for sanitised comment HTML and Editor's module, which loads only from the page's own origin, the comments script's, or an endpoint given in code, and a `nonce` option for the scripts and stylesheets the thread loads.
- Add `mountThread()` on any element, which gets what the stylesheets and the script need to draw it, and `Comments.mountThread()`.
- Add `form()` and `replies()` to an override of the whole `comment` part, so Reply, Edit and replies keep working.
- Add links to a comment by the number in its permalink, looked up once for the page and opened only in that comment's own thread.
- Add drawing a thread again when a morphing page swap takes its drawn contents away, such as Turbo 8's morph refresh, with the same controller, its options and listeners, what's typed in its forms, its component hosts and its focus, in batches as a first load. A thread waiting to load draws its waiting state again, an element a site adds beside a thread is left alone and kept through a swap, and a swap that makes the root another owner's mount point starts that owner's thread, carrying the site's elements over.
- Add `@verbb/comments-browser/renderer`, the renderer itself, for code that mounts threads itself and wants a controller at once.
- Add `@verbb/comments-browser/form`, with `commentForm()`, which posts from a site's own `<form>` to `@verbb/comments-core`'s thread store with the site's spam protection mounted on it, for an interface drawn without a framework. React's and Vue's `useCommentForm()` are built on it.
- Add loading in pieces: `startComments()` is a small loader that imports the renderer when a thread nears view, and the comment forms are imported when someone heads for one, straight away for a signed-in member. `Comments.mount()` and `mountThread()` from the main entry return promises, since the renderer may not have loaded yet. The report dialog is a small chunk of its own, loaded when someone who can report opens a comment's ··· menu or reports, and Protect's spam protection is loaded with the forms, or when a member's thread brings a preparation, so a visitor who only reads downloads neither.
- Add drawing long threads in batches: the first 45 comments at once and the rest while the browser is idle, with a linked or focused comment drawn straight away. Each ··· menu builds its items when it first opens.
- Add custom fields from Comments' form field settings, above the comment box for those placed before the Comment element in the field layout and below it for the rest, with the box outlined once there are fields: every built-in input, an Assets field's file tray (in a chunk of its own, loaded by a form that has one) that checks each file's type, size and number before uploading it, then uploads it at once with Remove and Try again, and a fresh protection preparation for each guest upload. An edit draws exactly the fields the comment was posted with, with its files. The fields share one border colour with the comment box, inside a lighter frame that only groups them, take a focus ring on whichever has focus rather than on the whole form, mark required fields with a red asterisk, draw selects with their own arrow and Lightswitch fields as a switch (`role="switch"`, with the `comments__switch` class on the `checkbox` control). A new comment's form only collapses when focus moves elsewhere on the page or someone presses outside it, never for a press on a label or instructions, a switch to another window or a password manager's menu, and never while a field holds something someone entered. Custom field inputs are marked for password managers to skip (`data-1p-ignore` and the like), so a form with an Email field isn't taken for a sign-in form.
- Add custom field values on comments, inline after the date or in the `fields` part's labelled list, with web addresses and files linked only when they're `http` or `https`, with `rel="ugc nofollow noopener"`, and image files as thumbnails.
- Add field overrides by handle, `fields: { rating: { input, display } }`, through `Comments.configure()`, `mountThread()` and, as custom element names, `render()`'s config.
- Add what happens when a piece can't load: the thread says so with **Try again** in place of the loading line or Show comments, the form in place of the comment box, and the file tray in its field, where an edit keeps the comment's files. Chrome and other Chromium browsers never fetch a failed piece again on the same page, so there **Try again** for the thread or the form, and Reply or Edit after the form failed, reload the page once the server answers, and a thread that waited for **Show comments** then shows straight away. The file tray's **Try again** loads it again without a reload, so a comment being written stays.
- Add `files` and `upload()` to an Assets field's input override, whose value is the list of file IDs the form posts.
- Add framework components as part and field overrides, given as `{ component }`. The renderer draws an empty `<verbb-comments-host>` in the part's place, the same element for as long as the part is drawn, and reports the hosts through the controller's `subscribeHosts()` and `getHosts()` or `mountThread()`'s `onHosts`, once after each draw that changes any, with the context a function override gets and `renderDefaultInto()`, which keeps Comments' own markup for the part current in an element of the component's. The React and Vue packages render their components into these hosts.
- Add `setOptions()` to the controller, which replaces a mounted thread's own `themeConfig`, `parts`, `fields`, `labels` or `loadEditor` and redraws it, following input overrides given or taken away while a form is open.
- Add `data-comments-adapter`, which keeps the plugin's script, `Comments.mount()` included, from starting an adapter's mount point. `Comments.mount()` also leaves alone threads another copy of the renderer draws, and `/renderer`'s `mountThread()` stops a thread the plugin's script started on its element and draws its own with the options given.
- Add the browser events `comments:before-action`, `comments:before-submit`, `comments:viewer-loaded`, `comments:vote-changed` (with `vote`), `comments:report-changed` (with `reported`, false after a withdrawal), `comments:follow-changed` (with `following`) and `comments:comment-deleted`, for an author deleting their own comment, where a moderator's removal is `comments:comment-moderated`. `comments:comment-created` and `comments:comment-updated` name the comment as `commentUid`, as every other event does.
- Add `data-comments-load-mode` on a thread's mount point. A thread's own load mode, from `render()` or `mountThread()`, wins over the one `Comments.configure()` gives, which applies to threads that don't set one.
- Add their own classes for **Show comments** (`comments__show-comments` and `comments__show-comments-button`) and the failed load's **Try again** (`comments__load-error` and `comments__retry`), with `comments__load-more-button` on **Load more comments** and **Load more replies**, `comments__follow` on **Follow** and `comments__toast` on the toast.
- Add `--comments-color-avatar-0` to `--comments-color-avatar-7`, the colours behind people's initials.
- Add the visitor's own badges to the "Posting as" line, as their comments show them.
- Add GIFs from GIPHY when the site turns them on: a GIF button beside Cancel in the plain form, opening a picker that searches GIPHY from the browser in a chunk of its own, loaded only when someone opens it, with "Powered by GIPHY", GIPHY's results untouched and its pings. The chosen GIF shows under the text with Remove, can be posted on its own, and an edit sends it only when it changed. A comment's GIF is drawn at its size when it's known, so the page doesn't move as it loads. The new `comments__gif-*` classes are in `markup/classes.json`. With rich authoring, Editor's own GIF control in its toolbar takes over, and the form posts the GIF chosen there. The search is Editor's (`@verbb/editor/gifs`), so this package now depends on `@verbb/editor` for it, without loading Editor itself.
- Add folded comments and author scores from Comments 3. A comment the site folds after reports or downvotes shows its author and actions with “Comment marked as inappropriate” or “Comment hidden due to low rating” and a **Show comment** button in place of its text, GIF and field values, which opens it for that page view and moves focus to it. An author's score shows beside their name as `+12`, `0` or `-3`. The new `comments__folded*` and `comments__author-score*` classes are in `markup/classes.json`.
